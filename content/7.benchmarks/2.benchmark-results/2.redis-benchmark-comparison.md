## Redis backend performance (comparison)

This suite compares the backend cost of three Redis rate limiting approaches under the same client concurrency and runtime.

How to run:

```bash
make stress-redis-compare
```

Environment:

- Redis: Docker Compose (`compose.yaml`) on Docker Desktop (server `linux/arm64`)
- Client: 16 threads
- Duration: 30s per case

Backends compared:

- `trypema` Redis provider (Lua sliding-window)
- `redis-cell` module (`CL.THROTTLE`)
- GCRA Lua script (equivalent to `go-redis/redis_rate` allowN)

Caveat: semantics differ (sliding window vs GCRA), so results are backend-cost comparisons, not strict behavioral equivalence.

Command captured (for reference):

```bash
make stress-redis-compare
```

Module-based approaches (like `redis-cell`) tend to be faster because the logic runs as native Redis module code with less Lua interpreter overhead and fewer internal steps than multi-op Lua scripts.

### Hot key (rate_limit_per_s=1000)

Workload:

- `--key-dist hot`: always uses a single key (`user_0`); `key_space` is ignored (effectively 1 key).

::div{class="not-prose overflow-x-auto min-w-0"}

| Backend | ops/s | p50 (us) | p95 (us) | p99 (us) | p99.9 (us) | max (us) | allowed | rejected | errors |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| `trypema` (Redis Lua sliding-window) | 48,165 | 329 | 427 | 481 | 865 | 3,271 | 30,000 | 1,415,016 | 0 |
| `redis-cell` (`CL.THROTTLE`) | 65,613 | 238 | 313 | 355 | 533 | 1,713 | 30,001 | 1,938,508 | 0 |
| `gcra` (Lua allowN-style) | 53,406 | 294 | 376 | 445 | 829 | 3,521 | 30,014 | 1,572,256 | 0 |

::

### Uniform keys (100k keys, mostly allowed)

Workload:

- `--key-dist uniform`: picks a random key uniformly from `key_space` keys (`user_0..user_{key_space-1}`).

::div{class="not-prose overflow-x-auto min-w-0"}

| Backend | ops/s | p50 (us) | p95 (us) | p99 (us) | p99.9 (us) | max (us) | allowed | rejected | errors |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| `trypema` (Redis Lua sliding-window) | 40,125 | 388 | 535 | 611 | 1,090 | 2,277 | 1,205,982 | 0 | 0 |
| `redis-cell` (`CL.THROTTLE`) | 60,678 | 250 | 325 | 377 | 2,163 | 18,271 | 1,823,059 | 0 | 0 |
| `gcra` (Lua allowN-style) | 53,632 | 296 | 377 | 423 | 659 | 1,223 | 1,611,110 | 0 | 0 |

::

Note: in the uniform-keys case, `redis-cell` showed occasional long-tail outliers (p99.9/max) even though p99 stayed low.

Key takeaways:

- `redis-cell` has the best p50 and highest ops/s in these runs.
- Between Lua-based options, GCRA is faster here, but it is not semantically equivalent to sliding-window.
