All strategies return a `RateLimitDecision`: `Allowed` (admitted and recorded), `Rejected { retry_after_ms, remaining_after_waiting, .. }` (denied and not recorded), or `Suppressed { suppression_factor, is_allowed }` (suppressed strategy only).

::warning
If you use the suppressed strategy, always treat `is_allowed` as the admission signal.
::

```rust
use trypema::RateLimitDecision;

match decision {
    RateLimitDecision::Allowed => {}
    RateLimitDecision::Rejected { retry_after_ms, .. } => { let _ = retry_after_ms; }
    RateLimitDecision::Suppressed { is_allowed, .. } => {
        if is_allowed { /* proceed */ } else { /* stop */ }
    }
}
```

## Rejection metadata

`Rejected` includes two best-effort hints:

`retry_after_ms` is a best-effort wait time until capacity is likely available, and `remaining_after_waiting` is a best-effort estimate of window usage after that wait.

They are intended for backoff guidance and client feedback, not strict guarantees.

## HTTP mapping pattern

One common pattern is to turn decisions into `429 Too Many Requests` responses:

```rust
use trypema::RateLimitDecision;

fn decision_to_status(decision: RateLimitDecision) -> (u16, Option<u64>) {
    match decision {
        RateLimitDecision::Allowed => (200, None),
        RateLimitDecision::Rejected { retry_after_ms, .. } => (429, Some(retry_after_ms)),
        RateLimitDecision::Suppressed { is_allowed: true, .. } => (200, None),
        RateLimitDecision::Suppressed { is_allowed: false, .. } => (429, None),
    }
}
```

::note
With suppressed, you may choose to return 429 only when `is_allowed == false`, or degrade differently (queue, lower priority, partial responses).
::
