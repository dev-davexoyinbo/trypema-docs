Suppressed is designed for graceful degradation under load.

This strategy is inspired by Ably's post on distributed rate limiting at scale: https://ably.com/blog/distributed-rate-limiting-scale-your-platform

It tracks all calls for a key, and (when suppression is active) it tracks how many of those calls
were declined by suppression.

Near and over capacity, the limiter suppresses a fraction of requests, returning
`RateLimitDecision::Suppressed { is_allowed, suppression_factor }`.

::warning
Suppressed returns `RateLimitDecision::Suppressed`. Always gate your request on `is_allowed`.
::

## Decision contract

Suppressed returns one of these decisions:

- `Allowed`: request admitted
- `Suppressed { suppression_factor, is_allowed }`: suppression logic is active; `is_allowed` is the admission signal for this call

Do not treat "variant == Suppressed" as denial. Treat `is_allowed` as the boolean gate.

::note
The suppressed strategy does not return `Rejected`. The "hard limit" is enforced by driving the
suppression factor to `1.0` (full suppression), which yields `Suppressed { is_allowed: false, suppression_factor: 1.0 }`.
::

## Operating regimes

Suppressed has three regimes for a given key:

### 1) Below capacity

When observed usage is below the base window capacity (`window_size_seconds * rate_limit`), it returns
`Allowed` and no suppression is applied.

### 2) At/near capacity

When observed usage is at/above the base window capacity but below the hard window capacity
(`window_size_seconds * rate_limit * hard_limit_factor`), it returns
`Suppressed { suppression_factor, is_allowed }`.

The `suppression_factor` indicates how aggressively the strategy is suppressing (0.0 to 1.0), and
`is_allowed` tells you whether this call is admitted.

### 3) Above hard limit

Once observed usage reaches the hard window capacity, the strategy enters full suppression:

- Returns: `Suppressed { is_allowed: false, suppression_factor: 1.0 }`
- Behavior: denies all calls (until usage falls back under the hard window threshold)

`hard_limit_factor` controls where full suppression kicks in.

## Counters per key

Suppressed maintains a per-key sliding window of counters:

- `total`: total number of calls observed for the key
- `declined`: number of calls declined by suppression (`is_allowed: false`)

You can derive accepted usage as:

```text
accepted = total - declined
```

## Algorithm (step by step)

For each call `inc(key, rate_limit, count)`:

1. Compute a suppression factor for the key (cached).
2. If `suppression_factor == 0.0`, admit the call.
3. If `suppression_factor == 1.0`, decline the call.
4. Otherwise, admit with probability `1.0 - suppression_factor`.
5. Record the call into the sliding window totals:
   - Always increment `total` by `count`
   - If declined, increment `declined` by `count`
6. Return:
   - `Allowed` if `suppression_factor == 0.0`
   - Otherwise `Suppressed { is_allowed, suppression_factor }`

## Suppression factor intuition

At a high level, suppression increases as perceived rate rises above the target.

Perceived rate is the maximum of:

the average rate across the whole window and the rate observed in the last 1000ms.

This makes the strategy react faster to short spikes.

## Suppression factor (exact)

The suppression factor is derived from the observed totals:

```text
average_rate_in_window = observed_total_in_window / window_size_seconds
rate_in_last_1s = observed_total_in_last_1000ms
perceived_rate = max(average_rate_in_window, rate_in_last_1s)

suppression_factor = 1 - (rate_limit / perceived_rate)
```

Notes:

- If `perceived_rate <= rate_limit`, the suppression factor is `<= 0.0` and suppression is bypassed.
- The factor is clamped to at most `1.0`.
- Higher perceived rate -> higher suppression factor -> lower probability of admission.

## Hard limit factor

Full suppression is controlled by `hard_limit_factor`:

```text
hard_limit = rate_limit * hard_limit_factor
```

Recommended starting point: `hard_limit_factor = 1.5` (50% burst headroom).

In window terms, full suppression begins when observed usage in the sliding window reaches:

```text
hard_window_limit = window_size_seconds * rate_limit * hard_limit_factor
```

## Caching

Suppression factor is cached per key to avoid recomputing it on every call:

- Local: cached in-memory and recomputed at most once per `suppression_factor_cache_ms`.
- Redis: cached in Redis with a short TTL so multiple calls reuse the same factor.

## Get the current suppression factor

Both providers expose a method to fetch the current suppression factor for a key (useful for metrics and debugging).

Local:

```rust
let suppression_factor = rl.local().suppressed().get_suppression_factor("user_123");
let _ = suppression_factor;
```

Redis:

```rust
use trypema::redis::RedisKey;

let key = RedisKey::try_from("user_123".to_string()).unwrap();
let suppression_factor = rl.redis().suppressed().get_suppression_factor(&key).await.unwrap();
let _ = suppression_factor;
```

## Usage (Local)

Local suppressed is synchronous:

```rust
use std::sync::Arc;

use trypema::{HardLimitFactor, RateGroupSizeMs, RateLimit, RateLimitDecision, RateLimiter, RateLimiterOptions, SuppressionFactorCacheMs, WindowSizeSeconds};
use trypema::local::LocalRateLimiterOptions;

let rl = Arc::new(RateLimiter::new(RateLimiterOptions {
    local: LocalRateLimiterOptions {
        window_size_seconds: WindowSizeSeconds::try_from(60).unwrap(),
        rate_group_size_ms: RateGroupSizeMs::try_from(10).unwrap(),
        hard_limit_factor: HardLimitFactor::try_from(1.5).unwrap(),
        suppression_factor_cache_ms: SuppressionFactorCacheMs::default(),
    },
}));

rl.run_cleanup_loop();

let rate = RateLimit::try_from(10.0).unwrap();
let decision = rl.local().suppressed().inc("user_123", &rate, 1);

match decision {
    RateLimitDecision::Allowed => {
        // proceed normally
    }
    RateLimitDecision::Suppressed {
        suppression_factor,
        is_allowed: true,
    } => {
        let _ = suppression_factor;
        // admitted while suppression is active (often degrade priority)
    }
    RateLimitDecision::Suppressed {
        suppression_factor,
        is_allowed: false,
    } => {
        let _ = suppression_factor;
        // denied by suppression (treat like 429)
    }
    RateLimitDecision::Rejected { .. } => unreachable!("suppressed strategy does not reject"),
}
```

## Usage (Redis)

Redis suppressed is asynchronous and returns `Result<RateLimitDecision, TrypemaError>`:

```rust
use std::sync::Arc;

use trypema::{HardLimitFactor, RateGroupSizeMs, RateLimit, RateLimitDecision, RateLimiter, RateLimiterOptions, SuppressionFactorCacheMs, WindowSizeSeconds};
use trypema::hybrid::SyncIntervalMs;
use trypema::local::LocalRateLimiterOptions;
use trypema::redis::{RedisKey, RedisRateLimiterOptions};

// Create Redis connection manager
let client = redis::Client::open("redis://127.0.0.1:6379/").unwrap();
let connection_manager = client.get_connection_manager().await.unwrap();
let sync_interval_ms = SyncIntervalMs::default();

let rl = Arc::new(RateLimiter::new(RateLimiterOptions {
    local: LocalRateLimiterOptions {
        window_size_seconds: WindowSizeSeconds::try_from(60).unwrap(),
        rate_group_size_ms: RateGroupSizeMs::try_from(10).unwrap(),
        hard_limit_factor: HardLimitFactor::try_from(1.5).unwrap(),
        suppression_factor_cache_ms: SuppressionFactorCacheMs::default(),
    },
    redis: RedisRateLimiterOptions {
        connection_manager,
        prefix: None,
        window_size_seconds: WindowSizeSeconds::try_from(60).unwrap(),
        rate_group_size_ms: RateGroupSizeMs::try_from(10).unwrap(),
        hard_limit_factor: HardLimitFactor::try_from(1.5).unwrap(),
        suppression_factor_cache_ms: SuppressionFactorCacheMs::default(),
        sync_interval_ms,
    },
}));

rl.run_cleanup_loop();

let key = RedisKey::try_from("user_123".to_string()).unwrap();
let rate = RateLimit::try_from(10.0).unwrap();
let decision = rl.redis().suppressed().inc(&key, &rate, 1).await.unwrap();

match decision {
    RateLimitDecision::Allowed => {
        // proceed normally
    }
    RateLimitDecision::Suppressed {
        suppression_factor,
        is_allowed: true,
    } => {
        let _ = suppression_factor;
        // admitted while suppression is active
    }
    RateLimitDecision::Suppressed {
        suppression_factor,
        is_allowed: false,
    } => {
        let _ = suppression_factor;
        // denied by suppression
    }
    RateLimitDecision::Rejected { .. } => unreachable!("suppressed strategy does not reject"),
}
```

## Concurrency notes

- Local suppressed is not a single atomic action across threads; under contention, multiple callers can temporarily exceed the target.
- Redis suppressed `inc(...)` is implemented as a single atomic Lua script execution per call.
