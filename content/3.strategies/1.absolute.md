Absolute is a deterministic sliding-window limiter.

It is the best default when you want predictable "allow/reject" behavior.

Behavior:

Below capacity it returns `Allowed`. Over capacity it returns `Rejected` with best-effort backoff hints.

::note
Absolute uses sticky per-key configuration: the first call for a key stores the rate limit; subsequent calls for that key do not update it.
::

## Algorithm (high level)

For each key, absolute computes a window capacity (`window_size_seconds * rate_limit`), checks current usage in the last window, rejects if adding `count` would exceed capacity, otherwise records the increment (coalescing into a recent bucket when applicable).

## Concurrency semantics

Absolute is best-effort under concurrency:

Admission check and increment are not atomic across callers, so multiple concurrent callers can observe `Allowed` and temporarily overshoot.

If you need stricter admission control, put synchronization around your calls (per-key locks) or use a centralized gateway.

## When to use

Use absolute when you need a hard cap per key, strict rejection semantics, and easy mapping to `429` responses with a retry hint.
