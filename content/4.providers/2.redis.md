The Redis provider enables distributed rate limiting across multiple processes or servers using Redis as a shared backend.

Requirements:

- Redis >= 6.2
- Async runtime: Tokio (`redis-tokio`) or Smol (`redis-smol`)

## Data model (high level)

For each user key, the limiter stores a few Redis keys under a prefix (default: `trypema`). The absolute strategy uses a hash for bucket counts, a sorted set for active buckets, and a string cache for the window limit.

## Semantics

- Each Lua script execution is atomic in Redis.
- Overall limiting is best-effort: concurrent clients may temporarily overshoot.

## Key constraints

Redis keys are validated and must not contain `:`.

```rust
use trypema::redis::RedisKey;

let _ = RedisKey::try_from("user_123".to_string()).unwrap();
let _ = RedisKey::try_from("user:123".to_string());
```
