[actix-trypema](https://crates.io/crates/actix-trypema) is actix-web middleware for Trypema. One
middleware covers every provider: local limits for a single process, Redis limits shared exactly
across instances, and hybrid limits shared through a local fast path.

## Install

```bash
cargo add actix-trypema trypema
# Redis and hybrid backends, plus the client that connects to Redis:
cargo add actix-trypema --features redis
cargo add redis --features tokio-comp,connection-manager
```

`trypema` provides `RateLimit` and `WindowSize`. Optional features:

| Feature | Adds |
|---|---|
| `redis` | The `Redis` and `Hybrid` backends, on tokio (the runtime actix-web runs on). |
| `json` | `JsonResponder`, a JSON body for rejections. |
| `metrics` | Decision counters and a backend latency histogram through the `metrics` facade. |

## A first limiter

Sixty requests per minute per client IP, in one process:

```rust
use actix_trypema::{Local, TrypemaLimiter, extract::PeerIp};
use actix_web::{App, HttpServer, web};
use trypema::{RateLimit, WindowSize};

#[actix_web::main]
async fn main() -> std::io::Result<()> {
    // Build the backend once, outside HttpServer::new, so every worker shares one limiter.
    let backend = Local::new(WindowSize::seconds_or_panic(60)).expect("valid backend");

    let limiter = TrypemaLimiter::builder(backend)
        .namespace("ip")
        .extractor(PeerIp::default())
        .rate(RateLimit::per_minute_or_panic(60.0))
        .build()
        .expect("valid configuration");

    HttpServer::new(move || {
        App::new()
            .wrap(limiter.clone())
            .route("/", web::get().to(|| async { "hello" }))
    })
    .bind(("127.0.0.1", 8080))?
    .run()
    .await
}
```

The 61st request within a minute gets `429 Too Many Requests` with a `retry-after` header, and
the handler never runs. Admitted responses carry `x-ratelimit-limit: 60`.

## The building blocks

Every limiter is a backend plus three required choices:

| Choice | Builder call | Learn more |
|---|---|---|
| Where counts live | `TrypemaLimiter::builder(backend)` with `Local`, `Redis` or `Hybrid` | [Backends](/actix-web/backends) |
| Who a request is | `.extractor(..)` or `.extractor_fn(..)` | [Client IPs](/actix-web/client-ips), [Keys and custom extractors](/actix-web/keys) |
| How much is allowed | `.rate(..)` or `.rate_fn(..)` | [Limits](/actix-web/limits) |
| A name | `.namespace("ip")`, matching `[a-z0-9-]{1,32}` | below |

The namespace keeps limiters that share a backend apart: a per-IP limiter and a login limiter
both see the client `203.0.113.7`, but count it under `ip_r_203.0.113.7` and
`login_r_203.0.113.7`. It also names the limiter in headers, outcomes, metrics and logs.

`build()` validates everything and returns a `ConfigError` instead of panicking at request time:
a missing namespace, extractor or rate, an invalid namespace, or a fixed rate that admits less
than one request per window.

## What happens to a request

1. **Exclusions.** If an `exclude` predicate matches, the request is forwarded and not counted.
2. **Key.** The extractor names the client. If that fails, the key error policy decides; by
   default the request gets `400`.
3. **Allow list.** Keys passed to `allow_keys` are forwarded without counting.
4. **Rate and cost.** A per-request rate and cost are resolved; a cost of `0` forwards without
   counting.
5. **Decision.** The backend admits or rejects. Admitted requests reach the handler and get rate
   limit headers; rejected requests get `429` from the responder.

## Build once, clone everywhere

`HttpServer::new` runs its closure once per worker thread. A backend built inside the closure
gives every worker its own counters, multiplying the effective limit by the worker count. Build
the backend and the limiter before `HttpServer::new` and clone the limiter into the closure;
clones share one set of counters.

## Where to wrap

- `App::wrap` limits every route. `web::scope(..).wrap(..)` and `web::resource(..).wrap(..)`
  limit only their routes.
- actix runs middleware in reverse registration order: the last `.wrap` sees the request first.
- Put IP limiters outermost, before authentication, so unauthenticated floods are cut early.
  Put identity limiters (per user, per API key) inside the middleware that authenticates them.
- If an exclusion matches on paths, register `NormalizePath` so it runs before the limiter.

```rust
use actix_trypema::{Local, TrypemaLimiter, extract::PeerIp};
use actix_web::{App, web};
use trypema::{RateLimit, WindowSize};

let backend = Local::new(WindowSize::seconds_or_panic(60))?;

let per_ip = TrypemaLimiter::builder(backend.clone())
    .namespace("ip")
    .extractor(PeerIp::default())
    .rate(RateLimit::per_minute_or_panic(600.0))
    .build()?;

let login = TrypemaLimiter::builder(backend)
    .namespace("login")
    .extractor(PeerIp::default())
    .rate(RateLimit::per_minute_or_panic(5.0))
    .build()?;

let app = App::new()
    .wrap(per_ip) // every route: 600 per minute per IP
    .service(
        web::resource("/login")
            .wrap(login) // and /login: 5 per minute per IP on top
            .route(web::post().to(|| async { "ok" })),
    )
    .route("/", web::get().to(|| async { "home" }));
```
