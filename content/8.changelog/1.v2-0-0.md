v2 redesigns provider construction and configuration, then adds consistent live reads and
conditional history updates across both strategies and all three providers.

::topic-figure{topic="migration"}
::

## Breaking changes

- Removed top-level `RateLimiter` facade, `RateLimiterOptions`, and provider option structs.
- Build `LocalRateLimiterProvider`, `RedisRateLimiterProvider`, or
  `HybridRateLimiterProvider` independently.
- Replaced numeric configuration setters with `WindowSize`, `BucketSize`, `HardLimitFactor`,
  `SuppressionFactorCachePeriod`, and hybrid `SyncInterval`.
- Replaced millisecond decision fields with semantic `WindowSize` and `Duration` values.
- `RateLimitDecision` remains exhaustive, while fields of `Rejected` and `Suppressed` variants
  are non-exhaustive.
- `RateLimitComparator::Always` replaces old unconditional comparator naming.
- Conditional methods return `ConditionalSetOutcome`, not `(new_total, old_total)` tuples.

## Provider construction

```rust
use trypema::{RateLimiterBuilder, WindowSize};
use trypema::local::LocalRateLimiterProvider;

let provider = LocalRateLimiterProvider::builder()
    .window_size(WindowSize::minutes_or_panic(1))
    .build()?;
```

Builders return `Arc<Provider>` and start stale-state cleanup by default. Use
`disable_cleanup()`, `enable_cleanup()`, or `cleanup_enabled(bool)` during construction, then
idempotent `start_cleanup_loop()` and `stop_cleanup_loop()` controls afterward. Hybrid Redis
synchronization remains mandatory and independent of cleanup.

## Live reads

- Absolute `get(key)` returns live total as `u64`.
- Suppressed `get(key)` returns `SuppressedRateLimitSnapshot` with `total`, `total_declined`, and
  `suppression_factor`.
- Unknown reads return zero-valued results without creating limiter state.
- Reads may lazily evict expired buckets.
- Hybrid `get` overlays this instance's pending state; `get_estimate` may use initialized local
  state without Redis I/O.

## Conditional history updates

- `set_if(...)` evaluates `RateLimitComparator` against live total and replaces history only on
  match.
- `set_if_preserve_history(...)` retains newest or oldest history through
  `HistoryPreservation`.
- `ConditionalSetOutcome` reports `matched`, `previous_total`, and `current_total`.
- Comparator misses change no history, limits, metadata, or suppression caches.
- Matched calls redefine sticky window capacity; matched zero removes key state.
- Suppressed preservation keeps declined counts proportional when partially reducing buckets;
  additions represent accepted usage.

## Runtime requirements

Local provider is always available. Redis and hybrid providers require Redis 7.2+ and exactly one
runtime feature: `redis-tokio` or `redis-smol`.

## Migration sketch

| v1 | v2 |
| --- | --- |
| `RateLimiter::builder()` | `LocalRateLimiterProvider::builder()` |
| `RateLimiter::builder(connection)` | `RedisRateLimiterProvider::builder(connection)` or `HybridRateLimiterProvider::builder(connection)` |
| `.window_size_seconds(60)` | `.window_size(WindowSize::seconds_or_panic(60))` |
| `.rate_group_size_ms(10)` | `.bucket_size(BucketSize::milliseconds_or_panic(10))` |
| `.sync_interval_ms(10)` | `.sync_interval(SyncInterval::milliseconds_or_panic(10))` |
| `retry_after_ms` | `retry_after: Duration` |
| `(new_total, old_total)` | `ConditionalSetOutcome` |
