This patch release improves cleanup behaviour and test coverage across Redis-backed and hybrid limiters.

## Fixed

- **Active-entity tracking is now scoped per rate type.**
  The internal sorted set used for cleanup (`active_entities`) is now keyed as `{prefix}:{rate_type}:active_entities` instead of a single shared `{prefix}:active_entities`. This prevents cleanup of one rate type from accidentally removing entities tracked by another.

## Added

- **Hybrid absolute limiter: stale in-memory state is now evicted on cleanup.**
  `AbsoluteHybridRateLimiter::cleanup(stale_after_ms)` now retains only entries whose `last_modified` timestamp falls within the stale threshold, keeping in-memory `Accepting` and `Rejecting` state aligned with Redis cleanup.

- **Hybrid suppressed limiter: cleanup now clears in-memory state.**
  `SuppressedHybridRateLimiter::cleanup(stale_after_ms)` now removes stale `Accepting` entries by `last_modified` and clears all `Suppressing` entries, so requests start from a clean state after Redis cleanup runs.

- **`last_modified` field added to hybrid limiter in-memory state.**
  Both `AbsoluteRedisLimitingState::Accepting` and `SuppressedRedisLimitingState::Accepting` now include `last_modified: Mutex<Instant>`, updated on every state transition to support accurate stale-entry detection during cleanup.

- **`RedisKeyGenerator::get_all_entity_keys` (test-only).**
  Adds a helper that returns all 7 possible per-entity Redis keys for a given user key, regardless of which ones are currently written by the selected rate type. Cleanup tests use it to assert complete key removal with a single loop.

- **Shared test helper module `src/tests/common.rs`.**
  Adds `redis_url()`, `unique_prefix()`, `key()`, `key_gen()`, and `wait_for_hybrid_sync()` to reduce boilerplate across Redis-backed test files.

- **Comprehensive cleanup-loop test suite (`test_cleanup_loop.rs`).**
  Adds hybrid absolute and hybrid suppressed cleanup-loop coverage for stale-key removal, preserving recently active entities, and allowing fresh requests after both Redis and in-memory state are cleared.

- **Expanded Redis state tests for hybrid absolute and hybrid suppressed limiters.**
  Adds cleanup-focused tests covering key removal, active-entity survival, and post-cleanup request allowance. Key construction now consistently goes through `key_gen()` instead of hardcoded format strings.
