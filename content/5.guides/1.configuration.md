Trypema exposes three main tuning knobs (per provider):

`window_size_seconds`, `rate_group_size_ms`, and `hard_limit_factor` (suppressed strategy).

## Recommended starting point

```rust
use trypema::{HardLimitFactor, RateGroupSizeMs, WindowSizeSeconds};
use trypema::local::LocalRateLimiterOptions;

let opts = LocalRateLimiterOptions {
    window_size_seconds: WindowSizeSeconds::try_from(60).unwrap(),
    rate_group_size_ms: RateGroupSizeMs::try_from(10).unwrap(),
    hard_limit_factor: HardLimitFactor::try_from(1.5).unwrap(),
};
let _ = opts;
```

## Trade-offs

Larger windows smooth bursts but recover slower; smaller windows recover faster but are more sensitive to spikes. Larger coalescing is faster and smaller but makes backoff hints less precise; smaller coalescing is more precise but increases bucket count. A larger hard limit factor allows more headroom before hard rejects.

## Presets

| Scenario | Suggested starting point |
| --- | --- |
| Typical API | `window_size_seconds = 60`, `rate_group_size_ms = 10`, `hard_limit_factor = 1.5` |
| Very latency-sensitive | `window_size_seconds = 30`, `rate_group_size_ms = 1..5` |
| High throughput + many keys | `window_size_seconds = 60..120`, `rate_group_size_ms = 50..100` |

::warning
If you change configuration across instances with the Redis provider, you can get inconsistent behavior. Keep settings identical across deployments.
::
