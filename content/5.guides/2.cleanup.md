Trypema does lazy eviction during normal operations, but keys can still accumulate.

Use the cleanup loop to proactively evict stale keys:

```rust
use std::sync::Arc;
use trypema::RateLimiter;

fn start(rl: Arc<RateLimiter>) {
    rl.run_cleanup_loop();
}
```

## Custom timing

The default cleanup loop uses:

`stale_after_ms = 10 minutes` and `cleanup_interval_ms = 30 seconds`.

You can override it:

```rust
use std::sync::Arc;
use trypema::RateLimiter;

fn start(rl: Arc<RateLimiter>) {
    // Evict keys inactive for 30 minutes, run every 60 seconds
    rl.run_cleanup_loop_with_config(30 * 60 * 1000, 60 * 1000);
}
```

::note
The cleanup loop keeps only a `Weak` reference to the `RateLimiter`. Dropping all `Arc<RateLimiter>` references stops cleanup automatically.
::

## Redis caveat

Redis keys are cleaned up opportunistically by the cleanup loop.

Normal operations perform lazy bucket eviction. The cleanup loop uses a Redis-side index of active entities to delete per-entity keys that have gone stale.

Depending on your workload and key cardinality, you may still want external Redis monitoring and housekeeping.

## Runtime notes

With `redis-tokio`, Redis cleanup is spawned onto the current Tokio runtime. With `redis-smol`, Redis cleanup runs as a detached Smol task and only makes progress if you drive an executor.
